================================================================================
              TRAVONET-WG ANDROID: USERSPACE-СТРАТЕГИИ ДЕСИНХРОНИЗАЦИИ
================================================================================

Все стратегии ниже работают на нерутованном Android через обычные UDP-сокеты.
Raw-сокеты, CAP_NET_RAW, ручная L3-фрагментация и traceroute не используются.

Стратегия задаётся в .conf:

  [Interface]
  Strategy = junk(64) -> fake_udp(148, ttl=5)
  FakeTTL = auto
  PreJunk = 64

или в UAPI:

  strategy=junk(64) -> fake_udp(148, ttl=5)

--------------------------------------------------------------------------------
1. ВСТРОЕННАЯ СТРАТЕГИЯ (default / default-userspace)
--------------------------------------------------------------------------------

  mimic(quic) -> mimic(stun) -> jumbo_fake(1600) -> fake_udp(148, ipopt=ts) -> sleep(2ms)

Что происходит:
  1. mimic(quic)      — QUIC Initial (1200 байт), сбивает сигнатуры WireGuard.
  2. mimic(stun)      — валидный STUN Binding Request.
  3. jumbo_fake(1600) — крупный UDP-пакет; ядро фрагментирует его по IPv4.
  4. fake_udp(148)    — фейковый handshake с коротким TTL и TS-опцией.
  5. sleep(2ms)       — пауза перед легитимным handshake.

Алиасы default, 5packet, early-term, ipfrag2, split2 автоматически приводятся
к этой стратегии.

--------------------------------------------------------------------------------
2. МИНИМАЛЬНЫЙ PRE-JUNK + FAKE
--------------------------------------------------------------------------------

  junk(64) -> fake_udp(148, ttl=5)

Подходит для сетей, где DPI реагирует на сигнатуру первого пакета, но не любит
слишком сложные последовательности.

--------------------------------------------------------------------------------
3. МАСКИРОВКА ПОД DNS/QUIC
--------------------------------------------------------------------------------

  mimic(dns) -> junk(96) -> fake_udp(148, ttl=4) -> sleep(3ms)

DNS-запрос выглядит естественно для мобильного оператора; fake_udp с TTL=4
не доходит до зарубежного сервера.

--------------------------------------------------------------------------------
4. JUMBO + FAKE БЕЗ MIMIC
--------------------------------------------------------------------------------

  junk(64) -> jumbo_fake(1600) -> fake_udp(148, ttl=5, corrupt=true)

`corrupt=true` меняет тип сообщения fake-пакета (0x00/0xFF вместо 0x01), чтобы
не попадать под статические сигнатуры.

--------------------------------------------------------------------------------
5. IP OPTIONS SHIFT
--------------------------------------------------------------------------------

  mimic(stun) -> ipopt_shift(8, mode=ts) -> fake_udp(148, ttl=5)

`ipopt_shift` не отправляет отдельный пакет: на нечётных попытках handshake
отправляется с IPv4 Timestamp option, на чётных — с обычным 20-байтным
заголовком. Это помогает, если провайдер по-разному обрабатывает IP options.

--------------------------------------------------------------------------------
6. БЫСТРАЯ СТРАТЕГИЯ ДЛЯ СЛАБЫХ УСТРОЙСТВ
--------------------------------------------------------------------------------

  fake_udp(148, ttl=5)

Один фейковый пакет и сразу легитимный handshake. Минимум syscall'ов и памяти.

--------------------------------------------------------------------------------
7. СИНТАКСИС DSL
--------------------------------------------------------------------------------

Шаги разделяются "->", ";" или переводами строк.

  junk(size=64, ttl=64)
  fake_udp(size=148, ttl=5, ipopt=ts|rr|nop, corrupt=true|false)
  mimic(quic|stun|dns)
  jumbo_fake(size=1600, ttl=5)
  ipopt_shift(size=8, mode=nop|ts|rr)
  sleep(10ms)

Параметры:
  size/len  — размер UDP-payload (для jumbo_fake минимум 1500)
  ttl       — TTL конкретного шага (0 = NormalTTL/FakeTTL по умолчанию)
  ipopt     — IPv4 options: ts (timestamp), rr (record route), nop
  corrupt   — испортить заголовок fake-пакета

НЕ ПОДДЕРЖИВАЕТСЯ на нерутованном Android:
  frag(...)       — требует raw-сокет;
  fake_frag(...)  — требует raw-сокет;
  badsum=true     — требует ручной сборки IP/UDP-заголовков.

При встрече таких действий движок пишет предупреждение и использует
default-userspace.

--------------------------------------------------------------------------------
8. AUTO-TTL
--------------------------------------------------------------------------------

  FakeTTL = auto

Расстояние до сервера измеряется через IP_RECVERR / MSG_ERRQUEUE без root.
Итоговый TTL ограничивается диапазоном 3..7, чтобы фейк гарантированно
проходил зону ТСПУ, но не достигал реального сервера. При неудачном
зондировании используется FakeTTL=5.
